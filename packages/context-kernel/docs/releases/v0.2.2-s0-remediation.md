# v0.2.2 — S0 Trust-Boundary Remediation Candidate

> **Historical remediation status: superseded by v0.2.3 before independent re-audit.** A post-merge runner-clock regression (S0-003) was identified in this candidate. It is not cleared for S1, providers, real effects, AEON-IQ, or real-model work. See [`v0.2.3-s0-runner-clock-correction.md`](v0.2.3-s0-runner-clock-correction.md).

## Why this candidate exists

An external review summary of the v0.2.1 S0 audit candidate reported two findings. The report has been treated as a gate failure rather than a suggestion: S0 remains blocked until a focused independent reviewer verifies the fixes.

| Finding | Reported severity | Confirmed source condition | Candidate remediation |
|---|---:|---|---|
| **S0-001: caller-influenced lifecycle clock** | High | `AdmissionPolicy.admit()` previously selected `now or segment.created_at`; `BenchmarkAdapter.admit()` omitted `now`. A submitted segment timestamp could therefore determine expiry/not-yet-valid evaluation. | Admission requires an injected `verification_clock`; no admission method accepts or derives time from a segment. Benchmark adapters require the clock and `ScenarioRunner` supplies its own `ControlledClock.peek()`. |
| **S0-002: untrusted metadata controls compaction residency** | Low | `_is_protected()` previously returned true when caller metadata contained `active_invariant: true`. | S0 compaction protects only verified-principal required instruction, constraint, or output-contract segments. No metadata field can add protection. A trusted invariant registry remains deferred to S1. |

The external reviewer also reported a Docker Registry connection refusal while resolving an NVIDIA base image. This is recorded as an environment/network failure, not a verified S0 finding, because the S0 simulator path does not require that image. It must be reclassified only if the focused reviewer demonstrates that it is necessary for the agreed S0 test path.

## Exact candidate changes

The candidate modifies only simulator-safe source, tests, examples, and documentation.

| Area | Change |
|---|---|
| `context_kernel.admission` | Adds a mandatory injected `verification_clock: Callable[[], datetime]`; validates that it returns a timezone-aware value; reads it once per admitted batch; removes the `segment.created_at` fallback. |
| `survival_bench.adapters` | Makes `BenchmarkAdapter.admit()` require the trusted clock and passes it to both typed and flat provenance verification paths. |
| `survival_bench.runner` | Supplies the runner-owned `ControlledClock.peek()` for initial and delayed admission, preserving event-timestamp progression while avoiding a new tick. |
| `context_kernel.compaction` | Removes the `metadata["active_invariant"]` protection path. |
| Scenario fixtures | Remove legacy metadata trust markers that no longer affect authority or compaction. |
| Tests | Add expired/future timestamp-bypass cases, clock-required and naive-clock-negative cases, adapter-clock wiring, and external `active_invariant` compaction regression. |

The package version is `0.2.2`; the adapter and harness identities are `2.0.1`. The simulator remains `simulated-ploy/2.0.0`. These version changes ensure new traces can be distinguished from the pre-remediation v0.2.1 audit candidate.

## Required focused independent re-audit

The re-auditor must review the merged candidate commit and reproduce at least the following conditions independently.

1. Construct an expired attestation whose submitted segment has a timestamp inside the former validity window. It must reject against the reviewer-controlled runtime clock.
2. Construct a future-dated attestation whose submitted segment timestamp lies after issue time. It must reject as not-yet-valid against the reviewer-controlled runtime clock.
3. Confirm that admission cannot be created without a runtime clock and that a naive runtime clock fails closed.
4. Confirm every shipped initial, delayed, typed, and flat benchmark admission call receives the runner-owned clock; search for segment-derived lifecycle time or omitted clock paths.
5. Add an external-untrusted segment containing `metadata={"active_invariant": true}` under compaction pressure. It must not appear in the protected set and must remain eligible for summarization/eviction.
6. Verify that required verified-principal instruction/constraint/output-contract segments remain protected and that an impossible budget reports unsatisfied rather than evicting them.
7. Re-run the relevant full test, static, smoke, passive-audit, and replay gates from a clean checkout.

The reviewer must supply commands, source commit, raw results, any proof-of-concept, affected invariants, and a **Pass**, **Conditional Pass**, or **Fail** decision. A prior simulator replay, checksum, or internal CI pass is not a substitute for this independent decision.
