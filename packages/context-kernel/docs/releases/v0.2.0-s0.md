## Implemented S0 boundary

S0 replaces caller-declared trust with verifier-issued provenance, binds provenance to exact content and lifecycle scope, assigns opaque verified segment identities, and requires exact one-to-one joins through admission, assembly, compaction, and receipts. Empty allowlists deny admission.

The associated adversarial tests exercise forged authority, modified provenance, expiration/scope/revocation failure, replay, post-verification content substitution, duplicate logical IDs or verified UIDs, mismatched decisions, missing/surplus decisions, and duplicate receipt bindings.
